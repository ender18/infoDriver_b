# Frontend Vue 3 + Vuetify 3

## Contexto

Archivo a modificar: `src/views/modules/Companies.vue`
(único archivo, no crear nuevos)

El módulo ya funciona con CRUD completo. Solo hay que añadir los 3 campos
de Peibo al formulario de crear/editar y un indicador visual en la tabla.
No romper nada de lo que ya existe.

## Campos nuevos en el backend

El endpoint `GET /companies/` ya devuelve estos campos en la respuesta:
```json
{
  "peibo_customer_key":       "25ad137fc5778cde...",
  "peibo_api_key":            "d2c36018a3fb92d1...",
  "peibo_originator_account": "732020200001003675"
}
```

Los tres son opcionales (pueden ser `null`).
Se actualizan con `PATCH /companies/{id}` enviando solo los campos que cambian.

## Cambio 1 — Indicador Peibo en la tabla

Añadir una columna entre "Activo" y "Creado" que muestre si la compañía
tiene Peibo configurado (los 3 campos completos) o no.

### En `headers`:
```js
{ title: 'Peibo', key: 'peibo_status', align: 'center', sortable: false },
```

### Slot en la tabla:
```vue
<template #item.peibo_status="{ item }">
  <v-tooltip
    :text="peiboConfigured(item) ? 'Peibo configurado' : 'Sin configuración Peibo'"
    location="top"
  >
    <template #activator="{ props }">
      <v-icon v-bind="props" :color="peiboConfigured(item) ? 'success' : 'secondary'" size="18">
        {{ peiboConfigured(item) ? 'mdi-bank-check' : 'mdi-bank-off' }}
      </v-icon>
    </template>
  </v-tooltip>
</template>
```

### Helper en `<script setup>`:
```js
const peiboConfigured = (c) =>
  !!(c.peibo_customer_key && c.peibo_api_key && c.peibo_originator_account)
```

## Notas

- `showPeiboKey` controla la visibilidad de `peibo_customer_key` y `peibo_api_key`
  simultáneamente — un solo toggle para ambos campos sensibles.
- `peibo_originator_account` no se oculta (es una CLABE, no un secreto).
- Al editar, los campos Peibo se pre-cargan con el valor actual para facilitar
  la revisión — a diferencia de `api_subscription_key` que siempre se muestra vacío.
- Enviar `null` (no string vacío) cuando el campo se borra, para que el backend
  guarde `NULL` en BD y el icono de la tabla muestre "sin configurar" correctamente.
