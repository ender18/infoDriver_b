# PROMPT: Histórico de Saldos + Pagos Peibo — FastAPI + Vue 3 + Vuetify 3

## Estado actual (lo que ya funciona — NO romper)

- `driver_accounts` es una tabla de trabajo temporal por compañía.
  Cada vez que el usuario pulsa "Consultar saldos", se borra y se reemplaza
  con los datos frescos de Azure. Los campos de procesamiento (`process_status`,
  `process_balance_before`, etc.) se pierden al siguiente refresh.
- El módulo de frontend (`ToolsView.vue`, pestaña "Saldos con deuda") ya funciona
  con SSE para refresh y loop individual/masivo para procesar.
- Todo lo demás (validación de conductores, estadísticas) no se toca.

## Objetivo

1. **Histórico permanente** — crear `driver_accounts_history` para que cada sesión
   de consulta/procesamiento quede guardada para siempre.
2. **Campos de pago Peibo** — preparar el esquema para cuando se integre la plataforma
   de pagos (por ahora solo guardar la estructura, sin lógica de pago).
3. **Webhook Peibo** — endpoint para recibir la confirmación de pago que manda Peibo
   y guardarla en el histórico y en el log.
4. **Log de auditoría** — tabla `payment_log` que registra cada evento transaccional
   (refresh, proceso, pago iniciado, webhook recibido, error).

### Cambio en `refresh_driver_accounts` (SSE)

Al inicio del refresh, generar un `session_id = str(uuid.uuid4())`.

#### REGLA CRÍTICA — Todo o nada

El paso de "copiar al histórico + borrar driver_accounts" es una operación atómica.
Si falla cualquier parte, se hace rollback completo y se emite SSE de error.
**Nunca borrar `driver_accounts` sin haber confirmado la copia al histórico.**


## Fase 4 — Webhook Peibo

### Nuevo router `app/routers/webhooks.py`

```python
POST /webhooks/peibo
Content-Type: application/json
```

**Payload que envía Peibo:**
```json
{
  "transaction_id":       "PRfzTT1I1sE9lc87z77i",
  "tracking_code":        "PEIBO0000275001",
  "date_time":            "2026-05-12T10:36:00Z",
  "concept":              "Test Prueba Webservices",
  "reference":            "123457",
  "amount":               "10.00",
  "beneficiary_account":  "012180015760711095",
  "originator_account":   "732010100003232949",
  "originator_bank":      "90732",
  "originator_name":      "TACK SA DE CV",
  "originator_tax_id":    "XXX000000MN1",
  "type":                 "outgoing",
  "status":               "Liquidada",
  "refund_reason_code":   0
}
```

**Identificador:** el campo `tracking_code` es la clave que vincula el webhook con el
registro en BD. Se guarda en `peibo_tracking_code` al momento de iniciar el pago,
y el webhook llega con ese mismo valor para identificar a qué conductor corresponde.

**Lógica del endpoint:**

1. Extraer `tracking_code` del payload.
2. Buscar en **ambas tablas** por `peibo_tracking_code == tracking_code`:
   - En `driver_accounts` (sesión activa, puede o no existir aún)
   - En `driver_accounts_history` (sesión archivada, la más reciente para ese tracking_code)
3. Si no se encuentra en ninguna: log `webhook_error` y responder 200.
4. Guardar **todos** los campos del webhook en los registros encontrados (ambas tablas).
5. Si `status == "Liquidada"`, actualizar también `payment_status = 'success'` en ambas.
6. Log `webhook_received` con el payload completo.
7. Responder `{"ok": true}`.

```python
def _apply_webhook_fields(row, payload: dict):
    """Aplica todos los campos del webhook a un registro (driver_accounts o history)."""
    row.webhook_status              = payload.get("status")
    row.webhook_transaction_id      = payload.get("transaction_id")
    row.webhook_date_time           = payload.get("date_time")
    row.webhook_concept             = payload.get("concept")
    row.webhook_reference           = payload.get("reference")
    row.webhook_amount              = float(payload.get("amount", 0) or 0)
    row.webhook_beneficiary_account = payload.get("beneficiary_account")
    row.webhook_originator_account  = payload.get("originator_account")
    row.webhook_originator_bank     = payload.get("originator_bank")
    row.webhook_originator_name     = payload.get("originator_name")
    row.webhook_originator_tax_id   = payload.get("originator_tax_id")
    row.webhook_type                = payload.get("type")
    row.webhook_refund_reason_code  = payload.get("refund_reason_code")
    row.webhook_received_at         = datetime.now(timezone.utc)
    if payload.get("status") == "Liquidada":
        row.payment_status = "success"


@router.post("/webhooks/peibo")
def peibo_webhook(payload: dict, db: Session = Depends(get_db)):
    tracking_code = payload.get("tracking_code")

    # Buscar en tabla de trabajo (sesión activa)
    work_row = (
        db.query(DriverAccount)
        .filter(DriverAccount.peibo_tracking_code == tracking_code)
        .first()
    )

    # Buscar en histórico (sesión archivada)
    hist_row = (
        db.query(DriverAccountHistory)
        .filter(DriverAccountHistory.peibo_tracking_code == tracking_code)
        .order_by(DriverAccountHistory.fetched_at.desc())
        .first()
    )

    if not work_row and not hist_row:
        _log(db, 'webhook_error', payload={"reason": "tracking_code not found", **payload})
        return {"ok": True}

    # Aplicar todos los campos a los registros encontrados
    if work_row:
        _apply_webhook_fields(work_row, payload)
    if hist_row:
        _apply_webhook_fields(hist_row, payload)

    db.commit()   # un solo commit para ambas tablas

    _log(db, 'webhook_received',
         company_id=(hist_row or work_row).company_id,
         driver_id=(hist_row or work_row).driver_id,
         history_id=hist_row.id if hist_row else None,
         payload=payload)

    return {"ok": True}
```

**Nota de seguridad:** Peibo debe verificarse con un secret / firma HMAC en el header.
Por ahora aceptar cualquier request (red interna), pero documentar para implementar
la verificación cuando Peibo la habilite.

## Notas importantes

- **Nunca modificar el histórico** — los registros de `driver_accounts_history` solo se
  crean y actualizan, nunca se borran. El webhook puede actualizar campos `webhook_*` después.
- **Todo o nada en el refresh** — el bloque copiar-al-histórico + borrar-driver_accounts
  es una sola transacción. Si falla el insert en history, no se ejecuta el delete.
  Así se garantiza que nunca se pierda la sesión anterior por un error de BD.
- **El webhook actualiza AMBAS tablas** — `driver_accounts` y `driver_accounts_history`
  se actualizan en el mismo commit usando `peibo_tracking_code` como identificador.
  Si el registro ya pasó al histórico (nuevo refresh corrió antes de que llegara el webhook),
  igualmente se actualiza el histórico. Si aún está en la tabla de trabajo, también.
- **Peibo no está integrado aún** — los campos de pago se guardan en el esquema pero
  el endpoint de pago (`POST /tools/drivers/accounts/pay/{driver_id}`) se implementa
  en una fase posterior cuando se defina la API de Peibo.
- **El webhook siempre responde 200** — Peibo no reintenta si recibe error. Cualquier
  fallo de procesamiento se registra en `payment_log` pero la respuesta HTTP es siempre `{"ok": true}`.
- **El `session_id` del histórico** antes de esta migración se genera como
  `fetched_at.isoformat()` del registro existente (migración no destructiva).
- **El `payment_log` es append-only** — nunca se modifica ni borra. Es el trail de auditoría.
